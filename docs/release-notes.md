# NetRedirector v1.8.0

## UDP 代理修正：回程封包來源位址還原

這一版修正了 UDP 代理回程封包的來源改寫。若你曾遇過「TCP 走代理正常，但遊戲的 UDP 連線（配對、語音、QUIC）明明有送出封包卻一直連不上、或連上後馬上斷」，本版即為此修正。

### 問題原因

代理伺服器把遠端伺服器的回覆送回本機時，封包來源是**本機的 relay socket**。舊版只把來源「端口」還原成遠端伺服器的端口，來源「位址」卻留成本機位址，於是這個回覆看起來像是應用程式自己送給自己的。

遊戲客戶端使用的是 `connect()` 過的 UDP socket，這種 socket 會**直接丟棄**任何來源不是其對端的封包 —— 因此回覆全被丟掉，配對連線永遠建立不起來。位址與端口必須**取自同一筆連線記錄**才算真正還原。

### 修正內容

- **回程來源完整還原**：改寫來源時同時還原遠端伺服器的**位址與端口**（取自同一筆 flow 記錄），讓 `connect()` 的 socket 能正確接受回覆。
- **負載平衡 / Anycast 後端放行**：部分遊戲後端位於負載平衡器後方，會由**不同位址**回覆。舊版以「位址必須完全相符」比對，這類回覆一律被當成「無對應連線」丟棄。本版改為先找完全相符者，找不到時以端口比對放行，並在主視窗日誌留下痕跡：
  ```
  UDP relay: response from unexpected address 1.2.3.4:26500 - matched by port
  ```
- **加大 UDP socket 緩衝**：relay 與每條 UDP 關聯的 socket 收送緩衝由系統預設提高至 1 MB。這些 socket 同時承載所有 UDP 流量，遊戲載入地圖、QUIC 起速時的突發量會把預設緩衝塞爆並丟棄資料包，玩家端即表現為封包遺失。

### 測試

新增主機端單元測試 `test_udp_rewrite`，把上述決策抽成純函式並鎖住行為（22 項斷言全數通過），涵蓋：

- 已知遠端 → 來源改寫為伺服器位址 + 端口；未知遠端 → 來源保持不變
- IPv4 只寫 4 位元組、IPv6 寫滿 16 位元組
- 完全相符優先，同端口不同位址走端口後備比對
- family 不符 / 未知端口 / 清空後 → 皆為不命中
