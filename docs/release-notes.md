# NetRedirector v1.9.0

## 設定不再「重開機就回預設」，VPN Gate 不再被環境斷線打爛

這一版處理兩個不同性質的問題：一個是**使用者設定會無聲消失**，一個是**VPN Gate
的節點穩定度會被跟節點無關的事件污染**。另外把 UDP 的歸因訊息降噪，讓 TCP 的
真訊號不再被淹掉。

> 如果你遇過「設定完之後重新開機，設定全部回到預設」，這一版務必更新。

---

## 一、修正：重新開機後設定回到預設

### 症狀

把自訂代理（IP／Port）、規則、Hub 綁定設定好，重新開機再啟動程式 ——
全部變回預設值，而且**畫面上完全沒有任何錯誤訊息**。

### 根因：不是讀不到設定，是**從來沒寫進去**

設定變更過去只存在記憶體，寫檔的時機**只有一個**：程式自己跑完關閉流程
（按下「完全關閉」或從系統匣結束）。而**新增／編輯代理、規則、Hub 綁定都不會寫檔**。

於是重新開機時：

- 程式是被系統結束的，**不會**走到存檔那條路；
- 就算 Windows 送出關閉通知，程式端的關閉處理也只有兩條路 ——
  勾了「關閉時縮到系統匣」會直接縮回系統匣並**拒絕關閉**，沒勾則跳出
  「要完全關閉，還是縮到系統匣？」的對話框**卡住關閉流程**；
- 兩者都不會存檔，最後由 Windows 強制終止行程。

再加上「開機時自動啟動」預設是開的，多數人設定完根本不會主動關閉程式 ——
等於幾乎必然踩到。

### 修正

1. **變更即存**：自訂代理（新增／編輯／刪除）、規則（新增／編輯／啟用停用／刪除）、
   Hub（新增／刪除／綁定切換／批次全選）、語言、Ping 目標、以及「關閉時縮到系統匣」、
   「啟動時自動檢查更新」、「自動管理介面計量」三個勾選項，變更後延遲 **800 毫秒**
   自動寫入 `config.json`。連續操作會合併成一次寫檔，不會一直磨硬碟。
2. **關機／登出前強制落地**：接上 Qt 的 `commitDataRequest`（Windows 在
   `WM_QUERYENDSESSION` 時發出），在行程被終止前同步寫檔；事件迴圈結束前
   再補寫一次尚未落地的變更。
3. **載入設定期間不排程存檔**：還原勾選框本身會觸發變更訊號，若不擋掉，
   剛讀到的設定會被立刻再寫回去（還原中途失敗時更會把「半套」狀態覆蓋成正式設定檔）。

順帶一提，因為關機時不再需要經過關閉對話框，**重新開機／關機也不會再被這個程式卡住**。

## 二、修正：VPN Gate 穩定度被「環境事件」污染

### 症狀

主網路（例如 PPPoE）中斷一次之後，**所有被試過的節點穩定度全部爛掉**，而且
再也不會自己恢復。

### 根因

斷線時，每個節點都會被記一次「連線失敗」與一次「被踢除」，`connect_attempts`
這個分母也被撐大。因為 `connect_rate` 是**終身比率**，一次大斷線就會在所有節點上
留下永久疤痕；又因為失敗懲罰上限（`0.20 × 5 = 1.00`）比加分項上限（`0.90`）還高，
**連續失敗 5 次在數學上必定讓穩定度歸零**。

### 修正

- 新增 `net_health.py`，用 **ICMP 探針**判斷主網路是否活著。選 ICMP 不是隨便選的：
  引擎的 WinDivert 過濾條件只有 `tcp` 與 `udp` 子句、**沒有 `icmp` 子句**，
  所以 ICMP 完全不進引擎，也不可能被 catch-all 的 PROXY 規則轉走。
  TCP/UDP 探針反而會在**主網路斷線時**經由同一段區網上還活著的手機代理「成功」——
  正好在最需要它的時候騙人。
- **有任何一次實際連線成功就一律不算環境事件**（主網路真的斷了不可能連得上）；
  否則才看探針，或「≥2 個節點全數失敗」的結構啟發式。
- 網卡監控端：**所有受監控網卡同一輪離線**且 ≥2 張 ⇒ 視為環境事件。此時仍記錄
  session 時長（真實資料），但**不記踢除次數**。
- **兩道保險**（這個專案反覆被「靜默死路」咬）：實際連線成功就立刻推翻探針判定，
  之後不再用它阻擋派發；判定 DOWN 期間仍每隔 120 秒硬試一次確認性派發。
- **復原工具**：節點面板新增「重置穩定度」按鈕；另有 `forgive_failures()`
  只清連續失敗次數、保留歷史比率。

## 三、降噪：UDP 的歸因失敗改用獨立節流槽位

同一句「could not be attributed」對 TCP 與 UDP 意義完全不同：

- 對 **TCP** 它是**真訊號** —— 連線追蹤狀態機被問到一個它從沒見過的 flow；
- 對 **UDP** 它是**常態** —— UDP 沒有 `TIME_WAIT`、沒有握手，socket 常常在查表前
  就關掉了（Windows 的 DNS Client 是慣犯），而 datagram 反正原樣送出、與沒開引擎相同。

兩者共用一個節流槽位時，一個忙碌的 DNS 用戶端就能把 TCP 的訊號淹掉 ——
實測引擎日誌裡 **72%** 的行都是這一類。

現在 UDP 走自己的槽位（60 秒視窗），TCP 的視窗（5 秒）刻意不動，因為那裡縮短的
代價是漏掉真問題。`test_logging` 補上 4 項回歸守衛，其中一項專門在防「有人把
兩個槽位併回一個」。

## 升級方式

使用內建自動更新即可。若更新流程本身有問題，直接下載本頁 zip 手動覆蓋
（`NetRedirector.dll` 必須與執行檔同目錄）。

> 提醒：設定檔 `config.json` 放在程式目錄。**手動換版本時請不要把整個資料夾
> 直接刪掉重解壓**，否則設定會跟著消失；內建自動更新會自動保留它。
