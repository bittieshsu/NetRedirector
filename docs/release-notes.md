# NetRedirector v1.8.1

## 更新下載修正：不再卡在 96%、速度 0 B/s

這一版修正自動更新下載可能「卡住不動」的問題。若你曾在「檢查更新」時看到進度條停在某個百分比（例如 96%）、速度顯示 0 B/s、連線數不再變動，放著很久都沒反應，本版即為此修正。

### 問題原因

多線程分段下載的停滯偵測寫在「收到資料之後」的迴圈裡。當某條連線完全不再送資料時，下載執行緒會卡在阻塞的 socket 讀取，永遠走不到停滯判斷那一行，因此「連續數十秒沒有位元組」根本不會被偵測到。唯一保底是 socket 讀取逾時，原本設 60 秒，再乘上每段重試與多個分段，看起來就像永久卡住。

補充：Windows 上無法從另一條執行緒關閉 socket 來取消阻塞中的讀取，因此不能靠「外部關閉連線」解鎖，必須從逾時與停滯偵測著手。

### 修正內容

- **縮短讀取逾時**：單次讀取逾時由 60 秒降為 20 秒，讓任何阻塞讀取都會自行逾時拋錯，帶動既有重試邏輯接手。
- **新增停滯 watchdog**：監看整體位元組數是否前進，連續 45 秒毫無成長即中止本次下載並改走下一條路徑，而不是無限重試同一批停滯區段。
- **分段等待加上上限**：停止後仍存活的下載執行緒最多再等一段固定時間就放棄，確保不會無限等待。
- **重試前重新探測**：重新取得簽名下載 URL，避免沿用過期的 GitHub 簽名 URL 而取得 403。

### 測試

新增回歸測試 `test_download_file_aborts_on_stalled_connection`，以「送出少量資料後即卡死」的伺服器驗證下載會迅速中止而非無限卡住。

---

> 提醒：這項修正隨 1.8.1 一起發佈。仍停留在舊版的使用者，其內建的舊版更新程式不受此修正影響；若更新時遇到卡住，請直接下載本頁的 zip 手動更新一次。
