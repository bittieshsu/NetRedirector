# NetRedirector v1.7.2

## 重要：舊版本（v1.7.1 及更早）可能「更新成功卻仍停在舊版本」

若你目前使用的是 **v1.7.1 或更早版本**，在**連續更新**時可能遇到這種情況：更新流程顯示成功、程式也重新啟動了，但版本號沒有變，仍是舊版。

**原因**：更新程式在替換檔案前沒有先卸載 WinDivert 核心驅動。驅動載入後會鎖住 `WinDivert64.sys`，使舊版目錄 `IntegratedApp.dist.old` 無法刪除；下一次更新時目錄交換因該殘留目錄已存在而失敗，而舊版程式又把「舊 exe 仍在」誤判為更新成功，於是重新啟動的其實是舊版本。

**解法（任一即可）**：

1. **重新開機後再更新** — 重開機會卸載驅動並釋放檔案鎖定，之後即可正常更新。
2. **手動清除殘留目錄** — 先關閉 NetRedirector，再以「系統管理員」身分執行：

   ```powershell
   sc stop WinDivert
   Remove-Item "<安裝目錄>\IntegratedApp.dist.old" -Recurse -Force
   ```

   完成後重新啟動程式並再次執行更新。

> 升級到 v1.7.2 之後，上述殘留會由更新程式自動處理，不需要再手動介入。

## 本版修正

- **修正連續更新卡在舊版本**：更新前先停止 WinDivert 驅動，釋放被鎖定的 `.sys` 檔案。
- **殘留舊目錄自動讓位**：`.old` 無法刪除時改名為 `.old.stale.<時間戳>`，不再阻擋目錄交換。
- **交換成功改為實際驗證**：必須確認 `.new` 已被消耗且 `.dist` 就位，不再只檢查 exe 是否存在。
- **鎖定檔案排程刪除**：仍無法刪除的殘留會註冊於下次開機自動移除。
- **更新日誌更明確**：逐項記錄清理結果，失敗可立即定位。
- **更新失敗時仍會重新啟動程式**：避免更新失敗後程式停在關閉狀態。
